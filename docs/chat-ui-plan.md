# 模型对话工作区实施与验收

目标：在现有静态控制台内完成本地 Chat 模型的多轮使用测试，复用 Python 网关与调度，不直接连接模型端口。

## 范围与阶段

- P0 协议核对：OpenAI 兼容 SSE、JSON 回退、流内错误、usage、取消。网关心跳不代表开始生成；首内容延迟包含排队，不提供虚构的排队耗时。
- P1 应用外壳：hash 导航、共享内存凭据、监控兼容、聊天按需加载。
- P2 对话链路：模型选择、发送、SSE、停止、错误恢复。
- P3 会话：System Prompt、参数快照、多轮、重试、答案版本、编辑最后用户消息、内存会话管理。
- P4 体验：安全 Markdown、代码复制与高亮、统计、JSON/Markdown 导出、响应式与键盘交互。
- P5 验证：协议及上下文测试、浏览器测试、真实 llama.cpp/Ollama 短请求、原功能回归、静态构建及回退说明。

## 不变量

1. 原 `/monitor.html` 仍进入监控，`#/chat` 进入聊天；导航不清除会话或中止生成。
2. 页面全局至多一个生成；切换会话仍能识别运行请求归属。
3. 每次发送冻结模型、参数和上下文。重新生成仅选中一个答案进入下一轮；编辑最后用户消息使后续答案失效。
4. 停止和失败的部分答案默认不进入上下文，可明确采用。
5. 模型切换默认新建会话，明确操作才能携带上下文。
6. 未设置参数不发送；不静默重试推理或截断历史；响应及事件大小有界。
7. 凭据只存内存，不进入 URL、会话导出或数据库；历史按后续 SQLite 方案自动保存。清除凭据中止生成并清空页面显示，已保存记录保留。
8. 内容渲染不接受原始 HTML，不自动加载远程图片，不执行模型生成内容。
9. token 用量只来自后端；不虚构精确队列时间或实际解码速度。
10. 静态资源先发布、HTML 最后替换，旧哈希资源保留。运行无需 Node。

## 当前协议证据

`gateway/app.py::_execute` 在流式排队前启动响应并发送注释心跳；`gateway/transport.py` 管理后端连接及取消隔离。因此 HTTP 200 与首个网络字节均不是模型开始生成的证据。浏览器停止接收也不能证明模型空闲。

## 发布与回退

开发使用 `npm run bundle`，只写 frontend/dist；完成验收后才使用 `npm run build` 发布 static。发布前备份已提交的入口、资源和清单；回退恢复同一版本整套静态文件，保留新旧哈希资源。该功能不要求重启模型服务。具体完成记录在实施验收后补充，不能以计划代替测试证据。

## 实际兼容性与停止语义

2026-09-13 对当前部署进行了真实短请求验证：

| 后端 | 参数 | 流式用量 | 独立推理字段 |
| --- | --- | --- | --- |
| llama.cpp | temperature、top_p、max_tokens、seed 已接受 | include_usage 开启后提供 | reasoning_content（客户端支持，当前短回答未返回） |
| Ollama | temperature、top_p、max_tokens、seed 已接受 | include_usage 开启后提供 | 当前服务返回 reasoning |

一次 512 token 长回答的停止测试触发现有网关 cancel_grace=10 秒后的 uncertain 隔离。该状态不会靠监控轮询自动清除，也不能以浏览器停止接收证明后端空闲。测试随后通过 3 次直接 llama.cpp slots 检查确认所有槽位空闲，并确认其他通道和模型无活动/等待请求后，重启网关恢复。模型进程未重启。页面展示恢复提示，首版不新增管理型恢复接口、不改变调度器释放条件。

## 后续优化：自动本机授权与浅色主题

按用户反馈，本机直连页面改为自动领取短期控制台会话，网关读取 `.api-key` 并继续管理后端鉴权；不把根 Key 发给页面。手动 Key 仍用于远程访问，清除凭据会清空页面中的对话显示且不会自动再登录；后续 SQLite 版本保留已保存记录。聊天页去除大面积暗绿，采用灰白层次、深色文字及蓝紫强调色。该更新需要加载新版网关代码，单独更新静态文件时会安全回退到手动凭据。

该轮优化验收：Python 全套 193 项中 189 通过、4 项 opt-in 跳过；新增本机授权 13 项在 Python 3.9/3.14 各通过，独立审查与原网关回归通过。前端 42 项单元/组件测试、54 项 Chrome/WebKit 测试通过，最终视觉修正后又验证 12 项相关浏览器用例。最终静态服务 4 项验证、构建一致性、Ruff/ESLint/类型检查通过。

真实 Chrome 验证了无手动 Key 自动连接、刷新更换临时凭据、一次 llama.cpp 聊天、桌面/手机浅色界面与凭据清除；真实 WebKit 验证了自动连接、监控 GET 与刷新重连。结果与截图位于 `work_dir/ui-refresh-validation/`。新资源 gzip JS 107.6 KiB、CSS 12.2 KiB；上线前确认所有通道与直接槽位空闲，只重启网关加载新授权逻辑。

## 本机会话存储更新

会话自动保存到忽略的 `data/chat-history.sqlite3`，支持刷新恢复、草稿、参数、推理内容及答案版本；保存失败不丢弃内存内容，版本冲突提供另存或显式重载。清除凭据不会删除已保存历史。完整边界见 [会话存储](chat-history.md)。

存储验收：前端 73 项单元/组件、Chrome/WebKit 78 项浏览器用例通过；Python 217 项中 213 通过、4 项 opt-in 跳过。真实 Chrome 完成一次模型请求并保存草稿/参数，关闭浏览器并重启网关后在 WebKit 恢复成功；重新认证保留数据，删除后刷新不复活，SQLite integrity_check 通过，数据库静态 URL 返回 404。测试产生的会话正文已清理，本地证据保存在忽略的 `work_dir/history-validation/`。
