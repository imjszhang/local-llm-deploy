# 本机会话自动保存

对话页通过同源网关将会话保存到项目根目录的 `data/chat-history.sqlite3`。SQLite 数据库在首次访问历史接口时创建，数据库使用版本化结构、事务和 WAL；不需要新增数据库服务或 Python 依赖。

## 保存与恢复

- 保存会话名称、模型、System Prompt、生成参数、未发送草稿、所有轮次与答案版本、思考内容、统计和请求快照。
- 输入和参数修改合并后自动保存，连续生成过程中定期保存部分输出，生成结束后立即保存。
- 页面显示“已自动保存”代表当前修改已收到数据库写入确认；网络故障、磁盘错误或版本冲突会明确提示，未保存内容保留在页面，可重试或导出。
- 打开页面先读取会话目录，再按选择加载具体会话。恢复记录不会重新发起模型推理；原来未完成的输出显示为已中断，部分答案默认不进入后续上下文。
- 刷新、重新打开浏览器或重启网关后，认证成功即可继续已保存的会话。最后一次确认前关闭页面可能失去尚未保存的修改；页面有未保存内容时会提示离开风险。
- 删除会话会删除本机保存的正文，后端保留不含正文的删除标记，阻止旧窗口把已删除的会话重新写回。
- 两个窗口同时修改同一会话时，版本冲突不会自动覆盖。可将本窗口内容保存为新会话，或者确认放弃本窗口未保存修改、载入数据库版本。

## 文件和访问范围

`data/` 整个目录被 `.gitignore` 排除，包括数据库、`-wal`、`-shm`、journal 和放在此处的备份。数据库不放在静态资源目录，不能作为网页文件下载；目录权限为 `0700`、数据库权限为 `0600`。

这是同一部署共享的本机历史库，不按临时登录令牌或浏览器建立不同用户账户。持有有效网关根 Key 的客户端和符合本机直连限制的控制台会话，可以访问同一份历史。没有设置根 Key 时，历史接口也不会向未认证的局域网请求开放。

凭据、Authorization 请求头和连接令牌不属于会话字段，不写入数据库。更换或清除凭据只会停止当前接收并清空页面内存，不会删除已保存历史；重新认证后重新读取。

数据库是本机文件，不自动上传 GitHub，也不进行云备份。需要额外副本时，可继续使用页面 JSON/Markdown 导出，或在停止网关后备份 `data/` 目录。数据库运行中不要只复制主 `.sqlite3` 文件而遗漏 WAL；在线备份应使用 SQLite backup API。

## 接口与维护

所有接口都要求鉴权，并返回 `Cache-Control: no-store`。每份会话最大 8 MiB，最多 1000 个未删除会话，达到限制会报错而不会淘汰已有记录。

| 请求 | 行为 |
| --- | --- |
| `GET /chat-api/v1/sessions` | 返回会话目录、版本和时间 |
| `GET /chat-api/v1/sessions/{id}` | 读取完整会话 |
| `PUT /chat-api/v1/sessions/{id}` | 写入 `{schema_version:1, session, revision}`；新建 revision 为 0 |
| `DELETE /chat-api/v1/sessions/{id}` | 删除，正文为 `{revision}` |

写入和删除采用乐观版本检查；过期版本返回 409，前端不得用无条件覆盖重试。服务端严格检查会话结构与字段，使用参数化 SQL。数据库不可用时返回错误，不悄悄转成只存内存的“保存成功”。

源码实现和数据库结构升级代码可以提交 Git；真实数据库文件保持在被忽略的 `data/`。首次升级前，旧版页面中尚未持久化的会话仍需先手动导出，新功能不能恢复已经因刷新而丢失的旧内存记录。
