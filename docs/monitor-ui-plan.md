# 监控控制台实施与验收

基线：`main@0c451c2`。实施分支：`codex/monitor-console`。目标是完成只读模型控制台、最小监控 API、前端测试及可复现静态发布。业务实现仍为轻量 Python；Node 仅用于开发和构建。

## 交付要求

- 顶部状态、访问设置、刷新/暂停、知识库入口。
- CPU/系统内存/负载及本页近五分钟趋势，明确采集有效性和最后成功时间。
- 全部注册模型与 Ollama 发现模型，搜索、能力/后端/状态筛选和排序；桌面表格、小屏卡片。
- 详情抽屉按实际监控支持提供信息、估算 token 预算、槽位及高级输出；不新增推理或正文持久化。
- 异常区区分认证、离线、未就绪、过期及结束状态不确定，不进行生命周期操作。
- 真实数值零与采集失败不同；进程 RSS 与系统内存分开；活动/等待/在途口径准确。
- 凭据仅在内存，清除时撤销请求与受保护数据；只向同源允许接口发送认证。
- 同资源单个在途请求、旧响应失效、隐藏/暂停/关闭详情取消，错误退避；刷新保持选择、滚动和焦点。
- 键盘闭环、抽屉焦点/Esc/回焦、文本安全渲染、减少动画、375/768/1440 宽度验收。
- Vue 3/TypeScript/Vite 源码与全部配置在 frontend/；发布产物在 static/，运行无需 Node。
- 保留 /、/monitor.html、/knowledge/ 和原 API 契约；原推理调度与服务进程归属不变。

## 页面与交互设计

桌面视图依次呈现导航、连接及更新时间、四张概览卡片、四类请求通道、需要关注的异常、完整模型清单。深色中性底色和少量绿色强调运行状态，警告与故障分别使用文字及颜色标识。小屏改为两列概览及模型卡片，筛选可换行，详情为全宽面板；不依赖横向拖动阅读关键状态。

模型清单保留离线和未加载模型，支持按名称/后端搜索，按能力/后端/状态筛选和排序。点击模型打开详情，保持原清单筛选及滚动位置。详情将生命周期、可用性、路由、当前网关活动分开显示；token 预算为网关预留估算，进程 RSS 不作为系统内存占用的加总。Ollama 展示版本、加载、量化和内存信息；Embedding、Rerank、Whisper 仅展示其实际提供的健康/进程信息。llama.cpp 的指标和槽位按源端支持情况展示。

高级输出默认关闭，只在用户明确展开后读取源端已存在的有限内容；滚动到上方阅读时不自动拉回底部。异常文本按纯文本渲染。抽屉与访问设置支持 Tab 闭环、Escape 关闭和回到触发按钮，减少动画跟随系统偏好。

| 场景 | 展示与行为 |
| --- | --- |
| 首次读取 | 骨架或未提供，不将缺失值画成零 |
| 正常采集 | 显示真实读数、来源成功时间和当前网关活动 |
| 采集失败且有旧值 | 保留旧值并标记过期；趋势断开 |
| 首次采集失败 | 显示未提供及原因，避免展示默认零 |
| HTTP 401 | 停止受保护轮询，显示访问设置和公开摘要 |
| 新 API 的快照 HTTP 404 | 明确提示升级网关，不误报模型清单为空 |
| 后端不支持指标 | 对应分区显示不支持，不继续探测该类服务的 llama 指标 |
| 请求结束不确定 | 保留活动占用并显示诊断，不提供自动强制释放 |
| 页面隐藏/刷新暂停 | 取消在途请求并停掉定时器，恢复时重新获取 |

## 目录及技术边界

`frontend/` 集中保存包管理、类型、Vite、浏览器测试等配置；源代码按 `api`、`domain`、`composables`、`features`、`components`、`styles` 分层。共享组件只处理呈现与交互，轮询和凭据不分散到各个组件。固定数据放在前端测试目录，生产构建不包含演示入口。

Python 的监控 DTO 和采集缓存位于 `gateway/monitor_api.py`；路由、认证、发现及调度继续使用现有模块。监控读取调度快照，不能新增另一套活动计数，也不能持有网络探测锁阻塞快照读取。测试分别归入 `tests/gateway/` 和 `frontend/tests/`。不新增根目录前端入口或配置文件。

## API v1 契约

新增 GET/HEAD `/monitor-api/v1/snapshot` 和 `/monitor-api/v1/models/{key}`；后者接受显式 `include_output=1` 读取源端已存在的有界调试输出。路径在静态处理之前明确分流，复用 ApiAuth。其余方法返回 405，未知路径 JSON 404。旧公开概览接口保持原样；未认证页面仍可显示其公开摘要。接口不暴露原始环境、完整命令、密钥或模型绝对路径。

字段定义以 `frontend/src/api/types.ts` 为共享契约。时间均为 Unix 毫秒。快照含 schema_version、snapshot_id、generated_at、来源有效性、system、lanes、models、diagnostics。模型分开表达 lifecycle、availability、routing、activity、monitoring_support；缺失读数为 null。详情按健康/指标/槽位/进程/Ollama 分区，各区有独立状态。

监控不能把一次 TCP 成功当作可路由，也不能根据缺少 PID 就确认进程不存在。活动计数作用域是当前网关，uncertain 保留占用。系统/目录/发现分别缓存，多浏览器共享采集；探测并发和响应字节有界。请求处理读取已发布快照，慢探测不持有快照读锁。

前端快照每五秒刷新，目录/发现由后端缓存；选中模型繁忙时每三秒读取详情，空闲时每十秒。成功认证后停止旧公开接口的额外轮询。同资源最多一个在途请求，取消/切换凭据/切换模型后利用请求代次丢弃迟到响应；错误退避最长六十秒。历史只保留当前页面五分钟并按采集时间去重，不持久化响应或凭据。

## 发布约束

先构建 frontend/dist，再同步明确归属的静态资源，禁止清空整个 static。HTML 重新验证缓存，hash 资源长期缓存；产物和源码一起提交，CI 检查可复现结果。保留匹配上版资源用于回退。当前部署单位仍是 Python 包加完整项目目录，wheel 不单独携带整个部署配置与静态目录。

候选先通过模拟数据/临时假后端验证，再只读核对实际模型状态。新增 API 的常驻网关切换应在无在途任务的窗口进行，模型无需重启。仅修改磁盘代码不等于已经完成网关上线。

发布顺序：保存上一版本的完整源码及匹配静态文件 → 在独立目录构建并验证 → 核对现有网关通道均无活动/等待且无不确定占用 → 切换网关代码并验证新 API → 发布 hash 资源及 manifest → 最后切换 HTML → 验证原 API、知识库入口与新页面。保持原 host、port、凭据来源及 LaunchAgent 归属。

回退先恢复上一版本 HTML 和对应静态资源，再在无在途任务时恢复网关代码并重启同一网关。若只发生样式问题，可仅恢复前端；若 DTO 或发现行为异常，应恢复匹配版本。不要删除模型权重、运行环境、PID 或凭据来回退页面。回退演练在临时项目与临时端口进行，验证旧页面→新页面→旧页面的资源可达性及 hash；不能以未执行的步骤作为完成证据。

## 完成审计

各阶段完成后记录实际命令、结果及截图路径。不能用 fixture 页面通过代替实际静态产物服务，也不能用轮询状态模拟代替真实并发和故障测试。初始资源预算：首屏 JavaScript gzip ≤200 KB、CSS gzip ≤40 KB。临时验证文件与报告放入 work_dir/monitor-validation/，凭据仅在认证请求中通过内存使用，不输出到日志、报告或截图。
